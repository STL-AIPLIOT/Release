- 평가: `sac_mlp_obs8_rangegate_bt_v1` 번들, BT 상대(`AIP_STIL.dll`), 60초, 결정적, 30판
- 기준선: `sac_mlp_obs8_iter400` 번들, **같은 평가 조건**의 30판 (`analysis/bt30/`)

## 2. 이 비교에는 교란이 있다 — 원인을 게이트로 돌릴 수 없다

**평가 조건은 동일하지만 학습 조건이 둘 다 다르다.**

| | baseline | 이번 |
|---|---|---|
| 보상 | 게이트 없음 | 거리 게이트 + closure |
| **학습 상대** | **`target_mode: fixed`** | **`behavior_tree`** |

`stil_sac_mlp_obs8_iter400.yaml` 은 고정 표적으로 학습했다. 이번 실행은 BT 상대다.
**변수가 둘이라 회귀의 원인을 보상 변경에 귀속시킬 수 없다.** 실험 설계 실수다.
분리하려면 baseline 과 상대까지 같은 `stil_sac_mlp_obs8_rangegate_v1.yaml`(고정 표적)을
돌려야 한다.

## 3. 다만 진단이 원인을 좁힌다 — closure 탓이 아니다

마지막 5초 구간을 호스트 `GeoMathUtil` 로 재계산했다 (30판).

| | 값 |
|---|---:|
| 고도 손실 중앙 | **1,449 m / 5초** (≈ 290 m/s 수직) |
| 거리 감소 중앙 | **−10 m** (이탈) |
| 종료 고도 중앙 | 298 m |
| 하강하면서 **접근**한 판 | **2 / 30** |
| 하강하면서 **이탈**한 판 | **28 / 30** |

`closure` 는 멀어지면 **음수**를 준다. 즉 28/30 판은 **보상이 벌하는 방향으로** 움직이며
추락했다. 추격에 이끌린 다이브가 아니다.

5초에 1,449 m 를 잃는 것은 기동이 아니라 **거의 수직 낙하**다.
보상 구조가 아니라 **고도를 보지 못하는 문제**에 가깝다 — obs[0] 은 추락선~시작 고도
구간을 전체 범위의 **3%** 로만 표현한다.

## 4. 결론과 다음 수

1. **200초 재측정은 하지 않는다.** 44.8초에 추락하므로 200초로 늘려도 같은 결과다.
2. **고도 관측 해상도 개선을 먼저 한다** (§6-5의 sqrt 인코딩). 이번 진단이 그 근거를 강화했다.
3. **보상 게이트 자체는 아직 기각하지 않는다.** 근거(원거리 pursuit 86.9%)는 유효하고,
   회귀의 원인이 게이트라는 증거가 없다. 관측을 고친 뒤 같은 상대로 다시 본다.
4. 보상만 분리해서 보려면 `stil_sac_mlp_obs8_rangegate_v1.yaml`(고정 표적, baseline 과 동일 조건)을
   돌린다. 다만 관측 수정 **전에** 돌려야 그 비교도 단일 변수가 된다.
